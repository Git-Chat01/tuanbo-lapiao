# 核心判断审查记录（2026-10-09）

本文记录本轮修复与发布前验证；实际部署状态以线上 `/health` 版本核对为准。服务与评分版本统一为 `2026-10-09-judgment-evidence-1`，不复用旧评分缓存；已交付的历史回执仍保留。可靠性与日志修复见 [运维说明](./reliability-operations.md)。

## 不变的业务标准

背景固定为新人刚被刀下去、复活差很多、没有固定支持者。只看两项核心：陌生观众能否听懂参与什么，当前希望观众做什么；另查真实风险。自我介绍、感谢、具体称呼、票种、票数、金额、按钮、精确缺口不是强制过关清单。

判断必须结合整稿。前面提出具体内容，后面邀请帮忙留下并继续这项内容，可以跨句成立。不能只截取“想让我留下”就否认前面的互动，也不能要求每一票换一个奖励。只有报到记名、礼貌求助或主播愿望时，仍不能自动判参与理由成立。

给出的修改应保留学员已有内容与能力边界。先讲清原句哪里断、只改同一类问题，并解释为什么这样改。通过表示文字在已知背景里成立，不保证观众付费或实际临场表现。

## 本轮发现与处理

| 问题 | 实际影响 | 处理 |
| --- | --- | --- |
| 主判断与恢复路径把局部误读、轻度乞求判成不同轻重 | 同稿忽轻忽重 | 区分局部姿态问题与严重消费强迫；两个路径同口径，不能自动通过 |
| 程序按词表替“模板腔”补引文 | 看似有证据，实际先定性后拼依据 | 去掉自动补证据；人设判断需两处不同位置的真实引用 |
| 引文允许从全文任意按顺序抽字 | 可能删掉否定、条件、数字或拼接不同句子 | 限制为实际原文及少量不改变主要断言的口语省略；严格来源字段与概括说明分开 |
| 把“观众可能只感到被逼”也判成必然心理 | 正确、审慎的解释被反复拦截 | 保留临近的不确定限定；明确的“一定会上票”等仍拦截 |
| 已判通过却仍写“只差一句” | 学员不知道到底过没过 | 安全门全部通过后，主卡确认可以开口练；可选润色不作必改条件 |
| 只有“参与理由”示范有专项复核 | 补动作、去失实承诺等改法缺少独立检查 | 所有新人未通过稿的实际示范都放回整稿检查；保留有效内容，不编能力或支持 |
| 删掉未验证示范后，仍留下相同错误指令 | 学员仍可能照错误方向练 | 保留已验证诊断和原句位置，替换掉未确认指令，不抹去评分 |
| 先修引文，后发现示范没用，唯一修复机会已用完 | 多等一轮仍没有具体有效改法 | 同一次有界修复同时携带引用、定位与示范问题；不增加无限重试 |
| 恢复判断临时要求票种、单位、精确缺口 | 按教练建议改完又被卡关 | 主判断、恢复、示范检查共用整稿承接标准；显式额外门槛交回核对，程序不擅自升分 |

一处重要的实测反例：教练把“扣字记名”改成“扣字—出词—当场接一句，补票后接着念下一个”，示范检查认可，恢复判断却又要求票种、单位和精确差额。该稿已经加入长期对照样本 `context-linked-continuation`，与原来的 `empty-comment-reward` 成正反对照。

## 判断与可靠返回的边界

主模型独立评当前稿，历史示范不混进当轮评分。程序核对实际来源、契约、一致性及已知业务边界；示范还需放回完整稿件检查。可修问题合并到一次修复，受统一时间预算限制。需要恢复时，按同一业务标准对当前稿独立生成短判断，不沿用坏报告，也不默认放行。

严格校验应针对实际证据与错误结论，不把正常概括、可选润色、未知观众心理或缺少非必填信息转成学员错误。恢复契约已经有逐字 `quote` 与人设双位置检查，不再对所有自由解释的引号追加不必要的逐字门槛。

## 验证方式与证据

- 离线 CI 共 27 组，包含新增 `tests/judgment-evidence.mjs`、扩展 `tests/teaching-check.mjs`；验证删否定/条件、数字与人物混用、跨句拼接、人设造证据、轻重一致、额外门槛、同时修引用和示范、复核不可用时不交付坏评分。
- 真实模型只使用仓库虚构话术、本地模拟案例存储与回执；不读取真实学员稿或生产案例库。正常判断与恢复判断分别运行，不能把 HTTP 200 当作教学正确。
- 完整带教测试对需修改样本检查示范是否存在、是否保留原有内容、是否清除同类错误，并实际采用改法再评一次；“有指导但无示范”不会冒充闭环通过。
- `tests/tmp_results/` 中保留本轮各批结果与模型诊断。早期失败留作调查依据，按实际失败定向修复和复测，不能把这些记录删除后声称从未失败。
- 本地真实 workerd/SQLite 测试覆盖断线后完成、不可变回执和失败终态；构建仅执行 `--dry-run`。

这些对照用例能证明已知问题受到约束，不能证明任意稿件永不误判。持续校准仍需把老师确认的误判变成正反样本，尤其是自然接梗、表达含蓄和同义改写；老师纠错不会未经审查自动改变评分标准。

模型长尾等待仍需单独治理：本轮一次复评主模型耗尽 63 秒，短恢复在约 3.6 秒后给出结果。结果能够恢复不等于等待体验已经足够好。此前的附属服务等待上限、不可丢稿和任务日志一并保留，后续必须依据真实任务耗时与成功率评估，不能用少数合成测试替代线上证据。


## 本轮完成的结果

修复与定向复测分批进行，每个场景取最后一次已完成观察：16 个正常判断场景均符合预期，其中 9 个有采用示范后的复评，修改目标均确认解决且复评通过。10 个独立恢复场景均符合预期。它们不是同一轮随机抽样的准确率，更不能解释为线上 100% 稳定。

最终统一整稿口径后，追加四个正反样本（单纯求助、扣字记名、具体互动加继续邀请、尊重预算），正常与恢复路径均通过；两个需改样本实际采用示范后也通过。完整离线验证 27/27，通过真实 workerd 测试与 Worker 构建演练。汇总证据保存在本地忽略目录 tests/tmp_results/judgment-quality-summary.json，逐批原始结果仍保留。
