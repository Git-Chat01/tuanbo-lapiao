# 批改质量自测清单

跑法：前端表单填好场况与话术提交（或 curl 调 `/api/coach`），人工检查批改报告。
**任一案例翻车 → 迭代 `worker/prompt.js` 的 system prompt → 全量重跑五个案例。**

## 案例 1：经典求情卖惨型（必须抓到）

- 场况：差一大截 / 最后几秒 / 主持施压催票 / 弹幕冷清 / 别家领先、各刷各的
- 话术：
  > 家人们帮帮忙，我第一次播，求求大家可怜可怜我，给我上点票吧，我要是被淘汰了就太丢人了，拜托大家了救救我。
- 检验点：
  - [ ] ③ 必须出现 ❌，且指出"把自己放低/求情卖惨"
  - [ ] 点评落到博弈逻辑："观众正在拿捏你，你还在配合"方向
  - [ ] ④ 认知突破落在"拉票是谈条件不是求情"
  - [ ] 报告结合了场况（提到主持施压/最后几秒）

## 案例 2：写得还不错的话术（不为批而批）

- 场况：差一点点 / 倒计时中 / 主持配合给台阶 / 弹幕有大哥观望 / 别家和我差不多、能挖
- 话术：
  > 还差一点点就到手了，大哥们看戏也看半天了，这个时候不亮一手啥时候亮？你们上，我保证下一关整活绝对不怂，说到做到。
- 检验点：
  - [ ] ✅ 占比 ≥ 一半，不硬挑毛病
  - [ ] ⑤ 方向是"再往前一步"而不是推翻重写
  - [ ] 点评提到"给大哥出手台阶"这条做对了

## 案例 3：空泛口号型（没给任何人递戏）

- 场况：差一大截 / 刚进环节 / 主持中立看戏 / 弹幕冷清 / 别家领先、各刷各的
- 话术：
  > 家人们冲啊！给我上票！一起创造奇迹！我一定能行的，大家相信我！
- 检验点：
  - [ ] 点评指出"没给任何人递戏"——主持、大哥、散户都没接上
  - [ ] ⑤ 示例具体到动作（如给大哥递存在感台阶），不是继续喊口号
  - [ ] 点评有圈内口语感，新人能看懂

## 案例 4：场况绑定型（不能输出通用点评）

- 场况：差一大截 / 最后几秒 / 主持施压催票 / 弹幕有人唱衰拆台 / 别家领先、在唱衰我
- 话术：
  > 大家别走啊，我还能抢救一下的，你们再给我一点时间，我一定可以的。
- 检验点：
  - [ ] 报告必须提到"主持在递戏"——施压催票时该接戏而不是顶戏
  - [ ] 提到时间筹码（最后几秒的用法）
  - [ ] 提到唱衰的风向怎么应对（把唱衰变成博弈素材）
  - [ ] 如果换成别的场况提交同一话术，报告应有明显不同（抽查验证）

## 案例 5：防代写检查（对案例 1-4 的每个报告都查）

- 检验点：
  - [ ] ⑤ examples ≤ 3 条，且每条 ≤ 25 字
  - [ ] 全文找不到一段"可以照读的完整替换话术"
  - [ ] 有"用你自己的话说"类提醒
  - [ ] 五段齐全：echo / reality_gap / line_reviews / one_thing / direction
  - [ ] line_reviews 覆盖了她写的每一句
