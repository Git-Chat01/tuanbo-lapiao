# 批改质量自测清单（v2）

跑法：curl 调 `/api/coach`（或前端极简表单提交），人工检查批改报告。
**任一案例翻车 → 迭代 `worker/prompt.js` 的 system prompt → 全量重跑五个案例。**

⚠️ **跑批必须用文件方式发送请求体**（`curl --data-binary @req.json`，JSON 文件 UTF-8 编码）。
在 Git Bash（MSYS）里把中文直接写进 curl 命令行参数会被编码损坏（UTF-8→GBK），
Worker 收到乱码，AI 会对着乱码编造点评（表现为 original 引用稿子里不存在的句子、红线检测=0）。
PowerShell 直传没问题；任何 Bash 脚本里的中文 body 都要走文件。

v2 报告结构：verdict 大字卡 → 诊断卡（card_type + card_why + audience）→ [红线横幅] → echo → one_thing → 逐句点评(折叠) → direction(summary + examples)

## 案例 1：经典求情卖惨型（必须抓到）

- 票况：`far`（差一大截）
- 话术：
  > 家人们帮帮忙，我第一次播，求求大家可怜可怜我，给我上点票吧，我要是被淘汰了就太丢人了，拜托大家了救救我。
- 检验点：
  - [ ] `verdict` = `off`
  - [ ] `card_type` = `logic`，`card_why` 指出"把自己放低/求情卖惨"
  - [ ] `audience` 点破：这话没对准任何人，是在求一个模糊的"大家"
  - [ ] `one_thing` 落在"拉票是谈条件，不是求情"
  - [ ] 逐句点评有 ❌，点评有圈内口语感，新人能看懂

## 案例 2：好稿过关型（敢给 passed）

- 票况：`far`
- 话术：
  > 还差一大截，家人们听我说：这把我认真准备了整活，票冲上去我马上给你们跳段新学的舞，不好看你们随便骂。大哥，你上几张，剩下我喊大家一人补一点，就差你了！
- 检验点：
  - [ ] `verdict` = `passed`
  - [ ] `verdict_reason` 说清楚为什么过：有支点、有人味、无 ❌
  - [ ] `audience` = 大哥（第一目标）+ 散户（补一点），对上号了
  - [ ] ✅ 占比 ≥ 一半，不硬挑毛病
  - [ ] `direction` 是"再往前一步"的微调，不是推翻重写
  - [ ] 前端应进入过关页（本地联调验证）

## 案例 3：空喊口号型（谁都没对上）

- 票况：`close`
- 话术：
  > 家人们冲啊！给我上票！一起创造奇迹！我一定能行的，大家相信我！
- 检验点：
  - [ ] `verdict` = `off`
  - [ ] `audience` 指出"谁都没对上"——没递戏给大哥、主持、散户任何一方
  - [ ] `direction.examples` 具体到动作（如给大哥递存在感台阶、给散户递参与感），不是继续喊口号
  - [ ] `one_thing` 一句话能带走：喊口号没人应，递戏才有人接

## 案例 4：票况绑定型（同一稿 far vs secured 报告必须不同）

- 话术（同一段，分别用两种票况提交两次）：
  > 大家别走啊，我还能抢救一下的，你们再给我一点时间，我一定可以的。
- 票况 A：`far` 提交一次；票况 B：`secured` 再提交一次
- 检验点：
  - [ ] 两次报告有明显不同：far 版要谈"翻盘理由/给谁递什么戏"；secured 版要谈"守住/别让保位变陪跑"
  - [ ] 两次 `card_why` 不能是同一句通用话
  - [ ] 报告里出现票况对应的筹码（far=要追票，secured=要稳票）

## 案例 5：AI 味识别 + 防代写 + 吸收闸门

- 票况：`far`
- AI 味话术：
  > 亲爱的家人们，你们的每一次投票都是对我梦想的助力，让我们一起见证奇迹的诞生，用你们的热情点燃这个舞台，爱你们哟！
- 检验点：
  - [ ] `card_type` = `persona`（人设卡），或 verdict 至多 `almost`
  - [ ] `ai_flavor` 指出哪句 AI 味（如"助力梦想""见证奇迹""点燃舞台"）
  - [ ] `verdict` ≠ `passed`（人设卡必不过关）
  - [ ] 后台自动吸收清单里**不出现**这条（吸收闸门：persona 不进库）
- 红线话术（另跑一条）：
  > 大哥们，都下注了吗？快给小妹上上票吧，小妹求求你们了。
- 检验点：
  - [ ] 前端出现红线横幅（红底白字，指出"下注"不能播）
  - [ ] `verdict` 强制 = `off`（绝不发过关页）
  - [ ] `redline_note` 有内容
  - [ ] 后台自动吸收清单里**不出现**这条（红线永不进库）

## 防代写通查（对案例 1-4 的每个报告都查）

- [ ] `direction.examples` ≤ 3 条，且每条 ≤ 25 字
- [ ] 全文找不到一段"可以照读的完整替换话术"
- [ ] 有"用你自己的话说"类提醒
- [ ] 新契约字段齐全：card_type / card_why / audience / verdict / verdict_reason / echo / line_reviews / one_thing / direction / ai_flavor / redline_note
- [ ] line_reviews 覆盖了她写的每一句

### prompt 迭代沉淀（跨轮教训）

1. **温度**：0.7 时同一稿每次换新挑剔点（好稿永远 almost）；0.3 锚定规则、判定稳定。
2. **判定规则要机械**：verdict = f(有无 wrong、有无支点)，"没有例外"写进 user prompt 输出要求段（system 长文里的规则会被稀释）。
3. **partial 功能导向**："没到位"=在场上没起到作用；"能写得更具体"是审美偏好，写微调建议不降 mark。
4. **句式判别写正反例**：模型会持续把"递台阶"误判成"求情"（就差你了/你上几张），必须写清"谁高谁低"与"决定权留给大哥"；写过的判别示例会被模型当示范句库用，要标注"判别示例≠示范句库"。
5. **防照抄**：参照案例注入后模型会把案例句子改几个字塞进 examples；约束=examples 必须是她原句的改写版+两条对象分开（大哥/散户）。
